Connecting a Microsoft Account

← Back to Settings

Subscribing to a calendar's published ICS/webcal link (the "Add a calendar" form on the Settings page) is read-only — Homeport can show those events, but can't create, edit, or delete them. Connecting a Microsoft (Outlook) account instead gives Homeport full read/write access to that calendar, so appointments can be added and edited from Homeport itself, not just viewed.

This works for a free/personal Outlook.com account just as well as a work or school Microsoft 365 account — the steps below are written for a personal account, since that's the more roundabout of the two.

One-time setup (about 5 minutes)

This is done once per Homeport installation, not once per person connecting an account — after this, every family member can connect their own account from the Settings page in seconds, with no further setup.

  1. Sign in at entra.microsoft.com with the Microsoft account you want to manage this from (it doesn't have to be the same account you'll connect to Homeport). If this is the first time that account has ever used Entra, it may need to provision a free tenant first — see the FAQ below if you get stuck here, it's the step most likely to trip you up.
  2. Go to App registrations → New registration. Give it any name (e.g. "Homeport"), set Supported account types to "Accounts in any organizational directory and personal Microsoft accounts", leave the redirect URI blank, and click Register.
  3. Go to Authentication → Advanced settings and set "Allow public client flows" to Yes, then Save. This is what actually lets Homeport's sign-in work — without it, nothing past this point will function.
  4. Go to API permissions → Add a permission → Microsoft Graph → Delegated permissions, and add Calendars.ReadWrite, offline_access, and User.Read (the last one is usually already there by default — just confirm it's present). None of these need admin consent for this kind of app.
  5. Back on the app's Overview page, copy the Application (client) ID — it looks like a long string of letters, numbers and dashes.
  6. Paste it into Settings → Calendars → Connected accounts, and click Save.
The Application (client) ID isn't a secret — it's fine that it's visible in Settings. It gets saved in Homeport's own database (not baked into docker-compose.yml), so it's specific to this one installation and never accidentally ends up shared if someone else copies this setup for their own household.

Connecting an account

Once the Application (client) ID above is saved, click "Connect a Microsoft account". Homeport will show a short code and a link to microsoft.com/devicelogin — open that link on any device (your phone is fine), enter the code, and sign in with the account whose calendar you want connected. Homeport polls in the background and finishes automatically once you approve it; no redirect back to Homeport is needed. Repeat this for additional family members' accounts as needed — each is tracked independently, and each adds its own default calendar.

Frequently asked questions

I can't sign in to entra.microsoft.com — it says I don't have access, or asks me to create a directory.

A plain personal Microsoft account (free Outlook.com, Hotmail, etc.) with no Azure/Entra tenant yet often can't register an app until it's associated with one. The free, fastest way to fix this is signing up for a free Azure account — it asks for a card for identity verification (a temporary ~$1 hold, not a real charge) and provisions a tenant for you automatically. Once that's done, entra.microsoft.com should work normally with the same sign-in.

Registering the app says "the ability to create applications outside of a directory has been deprecated."

Same root cause as above — the account isn't yet associated with an actual Entra tenant. Provisioning one (see the previous answer) resolves this too; there's nothing else to configure differently.

When I try to sign in, I get "Selected user account does not exist in tenant... needs to be added as an external user."

This means the app registration's Supported account types setting doesn't currently allow personal Microsoft accounts. Go to the app's Authentication page in Entra and confirm it's set to "Accounts in any organizational directory and personal Microsoft accounts" — this is editable after the fact, not just at creation time.

Do I need to put the Application (client) ID in docker-compose.yml or an environment variable?

No — paste it into Settings → Connected accounts instead. It's stored in Homeport's database, which keeps it specific to this one installation rather than something that could be accidentally checked into a shared config file.

A connected calendar just shows up named "Calendar" — can I rename it?

Yes — open that calendar's Customize panel on the Settings page (same place as the color picker) and there's a name field at the top. Useful once more than one calendar is connected, so you can tell them apart when choosing which one to save a new appointment to.

Can I connect more than one account — say, one per family member?

Yes. Each account is connected independently through the same "Connect a Microsoft account" button, and each adds its own calendar to Homeport. There's no limit built in.

A connected account shows "Needs reconnecting" — what happened?

Microsoft's sign-in tokens periodically expire and need to be renewed, which normally happens automatically in the background. If that ever fails, the account's status changes to "Needs reconnecting" — just click Connect again for that same account and sign in once more; nothing else is lost.
